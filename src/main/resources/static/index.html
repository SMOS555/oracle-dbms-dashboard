ADVANCED CONCEPTUAL CONSTRUCTS

Generalization & Specialization Hierarchies (ISA)

The system models 3 distinct ISA specialization hierarchies with disjointness and total/partial constraints.

Disjoint Specialization {d}

PRODUCT Hierarchy

PRODUCT (Superclass)
↳ PERISHABLE_PRODUCT (ShelfLifeDays, StorageTempC)
↳ HAZARDOUS_PRODUCT (HazardClass, HandlingNote)

Subclasses inherit PRODUCTID, PNAME, CATEGORY, UNITPRICE. Foreign key cascade maintains referential integrity.

Disjoint Specialization {d}

EMPLOYEE Hierarchy

EMPLOYEE (Superclass)
↳ MANAGER (LevelNo, Bonus)
↳ DRIVER (LicenseNo, Expiry)

Recursive relationship: SUPERVISORID points to EMPLOYEE.EMPID. Managers run warehouses; drivers handle deliveries.

Disjoint Specialization {d}

GOODS_MOVEMENT Hierarchy

GOODS_MOVEMENT (Superclass)
↳ SHIPMENT (DeliveryDate)
↳ GOODS_RETURN (Reason, RefundAmt)

Tracks transitions of goods between Warehouses and Customer Orders with forward or reverse logistics.

Weak Entity & Multivalued

Complex Structural Elements

  • Weak Entity: ORDER_ITEM (Identified by owner ORDERS; Composite PK: ORDERID + PRODUCTID)
  • Multivalued Attribute: SUPPLIER_PHONE (1NF normalization for multiple supplier phone lines)
  • Multivalued Route: DRIVER_CITY (Driver authorized transit routes across cities)
  • M:N Associations: SUPPLIES, STOCK, DELIVERY_DUTY

LAB EVALUATION REPORT

Academic Justification: Neo4j vs. Relational DBMS

1. Domain Problem: Why RDBMS Struggles with Supply Chains

Physical Supply Chains and Multi-Echelon Warehouses are connected networks. Tracing an order from customer back to origin supplier requires joining 7 relational tables (SUPPLIER → SUPPLIES → PRODUCT → STOCK → WAREHOUSE → ORDER_ITEM → ORDERS → CUSTOMER).

In Relational SQL, this produces O(Nk) join explosion, nested-loop latency, and complex queries. In Neo4j, relationships are physical pointers traversed in O(1) index-free adjacency.

2. Concrete Query Comparison

Relational Oracle SQL (7 Joins):
SELECT s.SNAME, p.PNAME, w.WNAME, c.CNAME
FROM SUPPLIER s
JOIN SUPPLIES sup ON s.SUPPLIERID=sup.SUPPLIERID
JOIN PRODUCT p ON sup.PRODUCTID=p.PRODUCTID
JOIN STOCK st ON p.PRODUCTID=st.PRODUCTID
JOIN WAREHOUSE w ON st.WAREHOUSEID=w.WAREHOUSEID
JOIN ORDER_ITEM oi ON p.PRODUCTID=oi.PRODUCTID
JOIN ORDERS o ON oi.ORDERID=o.ORDERID
JOIN CUSTOMER c ON o.CUSTID=c.CUSTID
WHERE s.SUPPLIERID='S01';
Modern Neo4j Cypher (Index-Free Pattern Match):
MATCH path = (s:Supplier {id:'S01'})-[:SUPPLIES]->(p:Product)
             <-[:STOCKS]-(w:Warehouse),
             (p)<-[:CONTAINS]-(o:Order)<-[:PLACED]-(c:Customer)
RETURN path;

3. Key Modern Database Advantages for this Project

  • Index-Free Adjacency: Physical edge pointers traverse multi-hop supply lines in sub-millisecond O(1) time regardless of graph size.
  • Agile Property Graph: Heterogeneous products (Perishable with ShelfLife, Hazardous with HazardClass) are modeled as polymorphic multi-label nodes (:Product:Perishable) without sparse null columns or subclass junction tables.
  • Single Point of Failure (SPOF) Analysis: Graph degree centrality identifies products with only 1 supplier, alerting logisticians to stockout vulnerabilities.
  • Free Cloud Tier: Fully managed cloud database on Neo4j AuraDB with Bolt binary protocol support.
